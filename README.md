## 📖 1. Project Overview & Problem Statement

Modern productivity tools suffer from a glaring paradox: **they force you to do tedious organizational work before you can do any actual work.**

When you're overwhelmed, procrastinating, or dealing with a late-night brain dump, the last thing you want to do is manually create folders, assign priorities, categorize tags, and plan breakdown steps. The friction of organizing often causes people to avoid starting altogether.

**The Lazy Payoff** is a local-first AI productivity assistant designed to cure digital procrastination. 
The core philosophy is simple: **do the work once, let AI handle the rest.**

Users simply dump unformatted thoughts, messy to-do lists, sprint meeting notes, or scattered lecture items into a clean workspace. With a single click, a locally running open-weight model (**Google Gemma 3 4B via Ollama**) turns the chaos into:
1. Categorized task domains (Study, Work, Personal, Communication, Other).
2. Suggested priority levels (High, Medium, Low).
3. Concrete, bite-sized **"manageable next steps"** designed specifically to lower cognitive friction and kill procrastination.
4. Persistent browser-based task boards and saved history with zero cloud dependencies.

## 🌟 3. Why Open-Source AI Must Be Central

The Lazy Payoff is not a SaaS wrapper around commercial, closed-source APIs. Local open-weight intelligence is fundamental to the project for five critical reasons:

1. **True Personal Privacy:** Brain dumps often contain private emails, unreleased project ideas, passwords, health appointments, or financial to-dos. Running **Gemma 3 4B locally via Ollama** ensures your raw text never leaves your computer or streams to third-party data centers.
2. **Zero API Charges:** There are no subscriptions, per-token metered bills, or surprise charges. Once weights are downloaded to your machine, inference is completely free of recurring cloud costs (subject only to local electricity and hardware).
3. **Model Sovereignty & Flexibility:** Users are free to experiment with any compatible model in Ollama (`gemma3:4b`, `llama3.2`, `mistral`, etc.) simply by changing an environment variable.
4. **Resilience & Offline Independence:** When working in airports, trains, or low-connectivity zones, you retain full access to your productivity pipeline without depending on remote cloud availability.
5. **No Telemetry or Tracking:** Zero user tracking beacons, advertising cookies, or telemetry surveillance.

## 🏗️ 4. Architecture & Technology Stack

```mermaid
flowchart TD
    subgraph Browser ["Client (React + Vite + Tailwind)"]
        UI["Workspace & Quick Actions"]
        TB["Interactive Task Board"]
        LH["Browser LocalStorage Engine"]
        UI -->|Send Tasks| TB
        TB <-->|Auto-Sync| LH
    end

    subgraph Server ["Local Backend (Node.js + Express)"]
        VAL["Validation & Size Guards (8k char cap)"]
        PRM["Factual Prompt Templates (Anti-hallucination)"]
        OLC["Ollama Client Service & Timeout Guard"]
        ERR["Centralized JSON Error Envelope"]
    end

    subgraph Engine ["Local AI Engine (Ollama)"]
        G3["Google Gemma 3 4B Model (Weights on Device)"]
    end

    UI -->|POST /api/ai/organize| VAL
    VAL --> PRM
    PRM --> OLC
    OLC -->|HTTP /api/chat (JSON mode)| G3
    G3 -->|Structured JSON Output| OLC
    OLC --> UI
```

### Stack Details
- **Frontend:** React 18, Vite 6, Tailwind CSS, Lucide React icons.
- **Backend:** Node.js, Express, dotenv, cors.
- **AI Engine:** Ollama running Google Gemma 3 4B (`gemma3:4b`).
- **Persistence:** Browser `localStorage` (saved history and interactive task board).
- **Security:** Strict input length validation (8,000 char cap), XSS-safe text rendering, non-HTML JSON mode.

## 🚀 5. Windows Installation & Setup Guide

### Prerequisites
1. **Node.js** (v18 or higher recommended; tested on v24.x)
2. **Ollama** installed on Windows ([Download Ollama](https://ollama.com/download/windows))

### Step 1: Install and Start Ollama with Gemma 3 4B
Open Windows PowerShell or Command Prompt:

```powershell
# 1. Pull the Gemma 3 4B model (approx 3.3 GB)
ollama pull gemma3:4b

# 2. Verify model is installed
ollama list

# 3. Ensure Ollama is running (it runs automatically as a Windows background service,
# or you can run it manually):
ollama serve
```

### Step 2: Clone & Install Dependencies

```powershell
# Navigate to project directory
cd the-lazy-payoff

# Install backend dependencies
cd server
npm.cmd install
cd ..

# Install frontend dependencies
cd client
npm.cmd install
cd ..
```

*(Note: On Windows PowerShell where script execution policy is restricted, use `npm.cmd` rather than `npm`)*

### Step 3: Configure Environment Variables

The project comes pre-configured with working defaults. If you need custom settings:

**`server/.env`:**
```env
PORT=3001
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=gemma3:4b
MAX_INPUT_CHARS=8000
REQUEST_TIMEOUT_MS=120000
```

**`client/.env`:**
```env
VITE_API_BASE_URL=
```
*(Leave `VITE_API_BASE_URL` empty in dev mode so Vite proxies `/api` directly to port 3001)*

## 💻 6. Running the Application

Open two terminal windows:

### Terminal 1: Start Backend Server
```powershell
cd server
node src/index.js
```
*Output: `🦥 The Lazy Payoff API server running at http://localhost:3001`*

### Terminal 2: Start Frontend Dev Server
```powershell
cd client
cmd.exe /c "npm.cmd run dev"
```
*Output: `Local: http://localhost:5173/`*

Now open **`http://localhost:5173`** in your browser!

## 🧪 7. Automated Test Suite & Reliability

The Lazy Payoff includes comprehensive automated tests using Node's native test runner (`node --test`):

```powershell
cd server
cmd.exe /c "node --test"
```

### Verified Test Cases:
- `✔ GET /api/health` — Verifies server health, uptime, and timestamp.
- `✔ GET /api/ai/status` — Checks Ollama connectivity and verifies `gemma3:4b` availability.
- `✔ POST /api/ai/summarize (empty input)` — Rejects whitespace and empty inputs with HTTP 400.
- `✔ POST /api/ai/summarize (missing input)` — Rejects missing `text` property with HTTP 400.
- `✔ POST /api/ai/summarize (oversized input)` — Rejects inputs > 8,000 characters with HTTP 413.
- `✔ POST /api/ai/organize (live Gemma 3 4B)` — Executes real neural inference on messy text and validates structured categorization.

## 🛡️ 11. Known Limitations & Future Roadmap

- **Inference Speed on Older CPUs:** On machines without GPU acceleration, Gemma 3 4B inference may take 10–25 seconds. The UI displays soothing "Slow and steady" animations to manage expectations.
- **Model Download Requirement:** Users must download the 3.3 GB model weights once via `ollama pull gemma3:4b`.
- **Future Improvements:**
  - Support for speech-to-text input (Whisper) for voice brain dumps.
  - Export task lists to standard `.ics` calendar files or Obsidian markdown notes.
  - Multi-model benchmarking toggle (e.g. compare Gemma 3 with Llama 3.2 on the same brain dump).
